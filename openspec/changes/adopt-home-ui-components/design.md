# Design

## Completion criteria

The document title remains the primary safe link, wraps without truncation, and is adjacent to its actual status and a separate alternatives trigger. Restore a composed paper/green document library with individually bounded, solid document surfaces and restrained depth. A border-top list with decorated buttons does not meet this contract. The following 2026-11-16 measurements supersede the former 24px heading and flat-row presentation; the interaction decisions below remain in force. Short viewports scroll normally. No decorative preview or explanatory dashboard is introduced.

## Decisions

Keep Homepage inventory and account ownership. Use Basecoat precompiled Item and input styles with existing shared theme tokens; retain the existing native settings dialog and use Web Awesome dropdown for alternatives. This replaces the earlier native details decision in `simplify-homepage-library`. Pin and self-host the browser distribution and its transitive imports under explicit Homepage routes. Preserve keyed link nodes and open menu state across polls, restoring focus to the document section if a focused destination disappears. Web Awesome 3.14.0 resets roving state after show and asynchronous slot updates; a Home-owned compatibility bridge keeps the focused item and the component’s internal `active` property aligned, observing its public tabindex changes and synchronizing before keyboard handling. During both manual and automatic opening, a single pending destination follows the latest user key, pointer or outside focus, while a manual opening with no user move retains the component’s default first item, while the component’s completion-time first-item focus does not replace that intent; removal or promotion updates its target. When two Home openings overlap, completion focus from an older closing menu and its Home restoration must not become the newer menu’s user intent; actual outside focus and key or pointer intent remain observable. For a close/reopen overlap, Home defers trigger and inventory reopening until both component show and hide completions; an attempted programmatic reopen that encounters the component’s still-active popup is closed and reopened after that transition. The queue is canceled on outside input or document removal. A user cancellation also closes an early programmatic open; consuming a normal queued reopen only removes its listeners. This defends direct public open changes during a transition; first-party inventory and trigger paths already use the phase guard. This version-specific dependency requires browser verification when upgrading. Native dialog continues to own modality and connection hash handling. Synthetic fixture serves the actual files without mutation endpoints.

Alternative labels count only the current safe menu entries, excluding the primary title. If a kind has multiple alternatives, append a one-based number in their displayed order (`HTML Reader 1`, `HTML Reader 2`, or `Paged Reader 1`, `Paged Reader 2`); otherwise keep its existing unnumbered label. Accessible labels use the same visible distinction. Numbers identify positions in the current menu, not service aliases or persistent identities, and may change on polling/promotion/demotion. Keep every safe occurrence and its existing keyed node/href; expose no URL or internal profile path as a label.

The brand text can shrink within its flex allocation and wrap unbroken text, while the logo and settings target retain their space. Header height grows naturally under text enlargement; text is neither hidden nor reduced to fit. The count's existing 8px margin owns heading/count separation, without an extra HTML separator space.

### Material, palette and ownership

Reuse the roles in `tools/flow-reader/web/theme.css`; their existing light/dark values are the palette, not new tokens to copy into shared CSS:

Use the full document perimeter and shadow together: the small fill difference alone is insufficient separation. Keep the page flat and calm, documents lightly raised, and menu/dialog transiently above them. Do not add glass, gradients, large animated blur, animated logo halos or a second nested collection of rounded cards. Solid surfaces work without backdrop-filter or reduced-transparency detection. Dark mode uses the explicit darker page and lighter document fill, visible edge and current shadow token; never invert the page.

Ordinary text (including status and placeholder) must reach **4.5:1**, large text **3:1**, and focus/essential control boundaries **3:1** against adjacent fills. The quiet document border is decorative, not the sole indicator of an actionable control. For search/input/select/button boundaries use a Home-owned edge derived from **85% muted + 15% surface in sRGB**, with solid muted as the unsupported `color-mix` fallback; verify both themes and every actual resting/hover/pressed pairing. No opacity reduction for text on hover. Use warning text only for an actual stale/error observation, with its real wording retained.

Any additional size, edge or presentation aliases use `--home-*` in `home.css` only. Do not modify `theme.css`, `theme.js`, Reader tokens or Web Awesome/vendor source. Existing Home-scoped Web Awesome palette mappings and public shadow parts may be styled locally; retain the local Basecoat 1.1.0 and Web Awesome 3.14.0 asset closure unchanged.

### Settings dialog

Keep the named native `dialog`, its existing controls/IDs, Escape behavior and browser modality. Width is **min(36rem, viewport minus 32px)**, radius **16px**, padding **20px** (**16px at <=480px**), solid surface, full 1px edge and `--shadow-card`; backdrop stays black at **45%**. Maximum height is **viewport minus 32px** using `100dvh` with a `100vh` fallback, and content scrolls inside the dialog. No fixed height, hidden-overflow trap or mobile fullscreen redesign.

Settings title is **22px/1.3, weight 650**; section headings **17px/1.4, weight 650**; body/inputs **16px/1.5** and help/notices **14px/1.5**. Header/close, theme selector, account and service sections have **16px** separation. Keep section dividers rather than nested elevated cards. The existing connection-state inset may use wash, 12px padding and 10px radius. Inputs/selects/buttons reuse Home control edges, focus and 44px targets; close and service summary also meet 44px width/height. Keep long account names, notices, capability inputs and service values inside the dialog width (`min-width: 0`, wrapping and stacked definition rows when needed).

### Behavior preservation and implementation boundary

The existing owners remain: Home HTML/CSS for presentation, `home.js` for inventory/keyed DOM, account and menu compatibility, shared appearance code for preference, Python services for inventory/auth authority. Prefer CSS and the current DOM; keep necessary HTML and label-only JavaScript changes local to presentation. Do not replace rendering with a new component tree, rename hooks, wrap away keyed link identity, change polling timing or redesign `home.js`.

- Preserve every full document name and actual state; `readerLink` scheme validation, safe HTML-first/Paged fallback and **all** safe variants (including duplicates keyed by occurrence) remain unchanged. No unsafe href or fabricated preview.
- Preserve identical keyed nodes across polls and search, focus fallback when a document/destination/trigger disappears, and focus following a surviving destination promoted/demoted between title and menu.
- Preserve Web Awesome roving `active`/`tabindex`, latest user focus intent, overlapping menu openings, public programmatic open during closing, show/hide completion ordering, queued reopen cancellation on outside input/Escape/removal, and listener disposal. CSS must not bypass these phases.
- Preserve inventory count semantics, search matching, loading/empty/no-results/error precedence and stale-state labels; existing visibility/offline/page-lifetime polling guards stay owned by Home.
- Preserve native settings semantics, Escape/focus return, initial/hashchange `#connection`, theme storage/System and cross-tab behavior. No new preference store.
- Preserve exact account IDs, instance/version freshness, in-memory capability, CSRF, explicit-action notices, permissions and hidden/disabled behavior. No credentials in URLs/storage and no real OAuth/account/model request during verification.
- Preserve 44x44 CSS-pixel minimum interactive targets, keyboard order and semantic activation. A long title must not collide with its separate menu target.

Home presentation must not modify shared theme policy, Reader content, reader-common policy, server/API authority or pinned vendor sources. Keep the existing Home asset delivery path and avoid a separate preview implementation.
