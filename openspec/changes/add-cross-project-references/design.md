## Context and Scope
ProjectService owns project creation and persistence; Profile owns validation. CrossProjectCatalog owns read-only identity resolution; CrossProjectNavigationStack owns return locations. NativeCrossProjectPreviewView presents an already resolved preview and emits an explicit callback. Existing reader/session owners retain document adoption, service lifecycle, source authority and location restoration.

## Directory registration
The IDE directory action supplies a directory, optional entry and optional projectRefKey to ProjectService. Discovery returns relative regular .typ paths from the root and two nested directory levels, excludes hidden directories and symbolic-link directories, and sorts root main.typ first then lexically. Without an explicit entry, root main.typ wins; otherwise a sole candidate wins. Multiple candidates require an explicit chooser selection. No candidate raises FlowError. An explicit entry must identify a regular .typ file inside the registered root, including after symbolic-link resolution. Selection/validation failure saves nothing. Defaults, first unused port, supplied user home and existing profiles are preserved; directory registration saves once and selects the new profile. The existing file-based addProject API remains unchanged.

Profile.projectRefKey is optional and legacy JSON decodes its absence as nil. Nil and empty mean unconfigured; a non-empty value must match `^[a-z0-9][a-z0-9-]{0,63}$` over the whole string. Existing profile validation remains in force.

## Catalog and target identity
projects.json is UTF-8 JSON: `{ "schema": 1, "projects": { "project-key": { "title": "Title", "pdf_url": "https://example.test/book.pdf", "references": { "label": { "page": 3, "text": "Theorem 1", "x": 0.2, "y": 0.4 } }, "ambiguous_labels": [] } } }`. Coordinates are optional, finite values; pages are positive and one-based. Loading is local and capped at 16 MiB by default; unsupported schemas and oversized input fail.

Explicit project key and label resolution takes priority over fallback. Labels declared ambiguous never become unique. Fallback parses `pdf_url#page=N`, requires exact PDF URL and page, and, when display text is available, matches entry.text or `entry.text + " of " + project.title`. All remaining candidates produce unique, ambiguous or unresolved results deterministically. No first-match navigation is allowed. Explicit profile.projectRefKey wins. Otherwise unconfigured profiles may match a case-insensitive folder basename or profile name, normalizing whitespace, underscores and hyphens to a single hyphen. Empty or normalization-empty catalog keys never match a profile. Duplicate profile matches return nil rather than guessing.

## Preview and navigation
Compose `final class NativeCrossProjectPreviewView: NSView` with an exposed `let surface = NativeDesignSurface()` child whose role is `.floating`, following NativeFloatingCapsule. NativeDesignSurface remains final and NativeAppDesign.swift is unchanged. The embedded surface supplies NativeAppDesign palette and floating shape; label typography and layout use the shared typography and spacing constants. Native button hit testing stays intact while header, snippet and padding dispatch body activation once.

The first reference click shows a compact preview without switching projects. Header text is `projectTitle · referenceText`; the bounded snippet and truncated flag describe the available excerpt. The interactive NativeDesignButton has identifier `crossProjectPreview.open`, empty title, image-only SF Symbol `arrow.up.right`, tooltip and accessibility label `해당 문서로 이동`; no visible `열기` text is allowed. Both button activation and a second click on the preview body emit the same content through onOpenTarget. Use NativeAppDesign floating palette, spacing and shape. Preview construction itself never navigates or starts a service.

The integrating reader validates the chosen target, pushes the origin profileID, documentTitle, anchor, blockID and scrollOffset only for a committed cross-project jump, and adopts the target project/anchor through existing session operations. Failed or cancelled jumps preserve the origin and stack. Back uses peek/pop with the same adoption rules, restores the saved location, and labels the action with the origin document title. The value stack retains at most 64 entries by default, evicts oldest entries, supports smaller capacities and treats non-positive capacities as disabled. Changing capacity trims immediately.

## HTML interoperability
HTML links should carry `data-project-ref-key`, `data-project-ref-label`, `data-project-ref-text` and `data-project-ref-title`. The `data-project-ref-*` identity metadata is preferred. Only links without explicit identity use projects.json fallback based on PDF URL, page and display text. An ambiguous or unresolved explicit identity must remain visibly unavailable rather than silently guessing from its URL. Neither path creates source coordinates or write authority. HTML/PDE producer and consumer edits are deferred outside this component's permitted files.

## Verification and integration limits
Compile production core and preview components with `/usr/bin/swiftc -swift-version 5 -warnings-as-errors`. Temporary-directory tests cover legacy decoding, key validation, discovery, registration defaults/failures, catalogs, identity ambiguity, bounded navigation, actual AppKit controls, offscreen layout and both activation paths. The manifest must cover every production Swift file exactly once. These component tests do not establish full IDE, reader jump/back or HTML integration acceptance; those need future owner wiring and GUI checks.
