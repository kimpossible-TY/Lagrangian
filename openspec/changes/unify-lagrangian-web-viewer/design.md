## Position and compatibility

Lagrangian is the native macOS app and canonical product/feature contract. `tools/flow-reader/web/` is its web-optimized projection, Lagrangian Web Viewer. Both use the single `flow_reader` backend and `tools/reader-common` for shared reader policy; concrete adapters own presentation, transport and geometry. For example, both resolve the same reference and preserve the origin on a failed jump, while native uses an AppKit popover and scroll offset and web uses a DOM popover and semantic reading anchor. User-visible branding does not rename `tools/flow-reader`, `flow_reader`, `data-flow-*`, `flow-reader-bundle`, LaunchAgent IDs, CLI flags, API routes or terminal/Neovim Lua statuslines.

### Catalog and resolution

Read the configured packages root's `local/project-references/0.1.0/projects.json` locally, with a 16 MiB byte limit; read at most limit plus one and reject oversize, invalid UTF-8/JSON, unsupported schema or invalid positions. Schema 1 is `{ "schema": 1, "projects": { "key": { "title": "...", "pdf_url": "...", "references": { "label": { "page": 1, "text": "...", "x": 0.2, "y": 0.4 } }, "ambiguous_labels": [] } } }`. Pages are positive one-based integers and optional coordinates finite. Catalog loading neither fetches PDFs nor starts services.

Explicit `data-project-ref-project` and `data-project-ref-label` take precedence; a declared ambiguous label remains ambiguous. Only absent explicit identity permits fallback: exact PDF URL plus `#page=N`, with display text, when present, equal to entry text or `entry text + " of " + project title`. Sort candidates deterministically and return unique, ambiguous or unresolved, never the first of multiple candidates. Explicit unresolved identities never use PDF fallback; ambiguous identities suppress activation. Unresolved links may open only their original URL after the existing external URL safety check; unsafe and fragment-only URLs do nothing.

For target profile mapping, an exact nonempty `projectRefKey` wins; otherwise only unconfigured profiles may match a nonempty normalized project key against profile name or root basename (case-insensitive, whitespace/underscore/hyphen runs become one hyphen). Duplicate matches fail closed. The native adapter supplies the profile inventory to this backend policy and retains authority over session adoption and editor consent.

The catalog is not a profile registry: each project key describes a reference collection; each label identifies one position in that project's document. A managed parent profile identifies a project root and entry document, and its associated reader profile supplies the service and URL. The source document's configured `packages` (`Project.packages`, passed by the manager's `--package-path`) selects the catalog; native uses its selected profile's packages, or `~/Library/Application Support/typst/packages` when empty, matching current behavior. Do not derive packages from a link or a target URL.

For web, a trusted server-side manager adapter obtains the current managed reader inventory from `ReaderManager.profiles()` and maps the resolved catalog project using the same policy. The browser never submits an inventory, filesystem path, port or service command. The preview response adds `target: { "profileID": "...", "documentID": "...", "readerURL": "...", "anchor": "..." }`, where the anchor is the resolved label and the URL is derived by the manager from the uniquely matched reader profile. Revalidate the mapping and document identity at jump time; the descriptor is a hint, not a bearer credential. The origin reader's document-scoped authorized API mediates resolution; target URLs must be same-origin managed reader routes with the existing ingress authorization. If the target is on another origin, has no authorized route, or is no longer unique, return unavailable and do not navigate. Do not expose the profile inventory, local roots, ports or editor descriptors to the browser. A deployment without a trusted manager adapter advertises no capability.

### Preview wire and accepted documents

Proposed document-scoped `GET /api/cross-project/preview` accepts either percent-encoded `project` and `label`, or `url` and optional `text`, but never both forms. Each value is at most 4096 UTF-8 bytes and the complete query at most 8192 bytes; reject missing, repeated, unknown, malformed or oversized parameters. It uses the same ingress authorization and document scope as existing reader APIs; inputs cannot name arbitrary local paths or acquire source-write authority. Successful JSON is `{ "project": "key", "label": "label", "title": "project title", "referenceText": "...", "snippet": "...", "truncated": false }`. Return 400 for malformed input, 413 for query limits, 404 for unresolved/unavailable accepted target, 409 for ambiguity, and 503 for unavailable catalog/service; use bounded, non-sensitive errors. A failed extraction may retain the catalog reference text as the native initial preview, but does not claim an accepted-document snippet. `/api/state` advertises `capabilities.crossProjectPreview: true` only when the catalog and preview service are configured and available; absent/false means clients must not call it. These wire details are planned WV02 contracts.

The manager matches the catalog project to exactly one managed reader profile, validates its root/entry and determines the service through that profile, not an HTTP-supplied address. It may start that managed service for preview and waits for the expected document and service incarnation; disposing the preview client never stops the shared service. The backend captures the published `AcceptedSnapshot` for that document and revision, checks `current` before and after import and extraction, and binds the import to the document ID and service incarnation (`pid` plus `startedAt`). A changed revision, inputs, document or incarnation makes the snapshot stale; rejected, stale, missing or failed imports cannot become snippets. Find the anchor first, then normalized case-insensitive reference text in display or canonical text. Extract at most four blocks in the same section, stopping before a later heading; prefer display text and fall back to canonical text. Limit output to 600 characters, append `...` within that limit when character-truncated, and mark `truncated` for either character or block truncation. Missing matches are unavailable, never a guess.

The endpoint returns 200 only with the complete snippet and target descriptor. An unresolved project, missing target profile or missing anchor and text match returns 404; a non-unique match returns 409. A service startup/readiness failure, stale or missing snapshot, or failed import returns 503, with no partial success payload. The native adapter can immediately show the already resolved catalog title and reference text while loading; on any extraction failure it retains that initial catalog text, never labels it an accepted snippet, and does not auto-navigate. The web adapter shows an unavailable state on a non-200 response and does not enable jump from an unverified target. Retry starts a fresh resolution and snapshot capture.

Native `FlowApp.swift` and `NativeReaderWindowController.swift` invoke the backend through the managed client, retain the initial catalog preview on load failure, reject stale async results and retain existing safe external URL behavior. Existing managed session adoption, origin-window tracking, and `windowInitialized` acknowledgment remain authoritative. Reserve only the target editor descriptor; return it on failure/cancel before consented attach, consume it when attach starts, retire it on disposal, and require fresh consent for later attempts. Success transfers tracking to the adopted window. Backend and strict native decoders are delivered together; no mixed-version projectRef support is implied. `handler_for(None)` must safely serve only allowlisted static assets without dereferencing missing document state.

For a native jump, resolve and revalidate the target profile, reserve its previously consented descriptor, then prepare a candidate managed session (starting or reusing the service and verifying the expected document). The origin window remains current during preparation. Attach consumes the reservation atomically when invoked; only `windowInitialized` from the current candidate commits the window and return entry. Failure, cancellation, timeout, or a stale acknowledgment disposes the candidate and preserves origin and history; an unattached reservation is returned, whereas an attempted attach requires fresh consent. Preview loading alone neither consumes editor consent nor commits a window. Web adoption has no editor descriptor or source-write authority: successful target document readiness and location restoration is its acknowledgment, and failed readiness leaves the origin active.

## WV03: shared return and web adapter (planned)

`tools/reader-common/navigation/cross-project-return.js` owns web-side return history and commit/restore policy with injected capture, adopt, restore and availability operations. Native Swift retains its platform stack but conforms to the same transition contract using shared behavioral fixtures; JavaScript is not embedded into the native app. An entry contains nonempty profile/document identity, document title, optional semantic anchor and block ID, plus adapter-specific location (native finite scroll offset; web semantic reading anchor and viewport offset). Never store raw DOM nodes or source-write authority.

Capture origin immediately before initiating a jump; retain it only after target adoption acknowledges success. Back peeks, adopts the origin and restores its location, then consumes the entry only after successful acknowledgment. Failure or cancellation preserves the current document and retained entry; stale completions cannot commit. Serialize transitions or invalidate older tickets, so overlapping jumps/Back cannot push or pop twice. Skip and discard deleted or non-uniquely matched profiles on Back; retain a valid target on actual adoption failure. Explicit Read or profile selection resets history. History is session-memory only, defaults to 64 entries, evicts oldest on overflow, trims immediately when capacity shrinks, and is disabled at non-positive capacity. Empty identities are never pushed.

The web adapter shows a popover on first click without navigating; a second click on the preview or its jump control starts adoption. Back restores the captured origin only after adoption succeeds. Existing same-document fragment navigation, `popstate` and browser history in `web/reader.js` continue to work: cross-project transitions use a distinguishable history state and route Back through the shared policy without double-pushing or consuming unrelated fragment entries. A browser Back event that cannot restore must leave the app's current location and return entry intact and reconcile its history state. Presentation and DOM geometry remain in the web adapter.

Web return state lives in versioned `sessionStorage` for the same-origin tab, keyed by an opaque session ID; it contains only the bounded serializable entries above and a transition ticket, never credentials or DOM objects. The ID and a cross-project marker/index are stored in `history.state`, not the full stack. Reloading a same-origin managed document rehydrates this session; reload in the same tab preserves it, while closing the tab ends it. Explicit Read/profile selection clears it; malformed or missing state is treated as empty. Other origins cannot share this storage and are unavailable for this workflow. The web adapter stages and validates the target in an isolated same-origin reader context while the current document stays visible; adoption swaps the ready document into the active reader and updates the same-origin URL with `pushState`, so a failed load cannot unload the origin. On jump, stage origin and target without pushing; after target readiness, commit the entry and one marked history state. On a marked browser Back, keep the committed current URL/state and peek the entry while adopting the origin; successful restore consumes it once and accepts the traversed history position. If adoption fails or is cancelled, retain the entry and use a guarded `history.go(1)` to restore the committed target position; suppress the compensating `popstate` and do not push a duplicate. If that forward position is unavailable, replace the current entry with the committed target URL and marker. Fragment states remain owned by existing fragment handling and do not consume the cross-project stack. Stale tickets cannot change either storage or history.
