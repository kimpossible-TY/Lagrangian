# Rename the product to Lagrangian

The private production repository is now `kimpossible-TY/Lagrangian`, but the installed app, data paths, packaging and current user-facing docs still identify the product as `tinymist-flow`. Align maintained product identity with Lagrangian without renaming Tinymist engine/protocol identifiers or rewriting historical verification records.

The first launch of the renamed app must migrate the existing Application Support and Logs directories without discarding the user's profiles, signing configuration, source history, reader state or recovery bundles. Keep the old paths as compatibility symlinks so existing LaunchAgents and integrations that still hold absolute legacy paths continue to work during the transition. Preserve `FLOW_*` environment variables and persisted profile schemas.

Extend `scripts/flow-app.py migrate-tail-hosting` and `restore-tail-hosting` with separate per-kind handlers so `typst-reader` services (together with their verified `reader/{engines,releases,documents}` artifacts, `reader/config.json`, `reader/bin/flow-reader`, reader LaunchAgent plists, and the background login manager LaunchAgent) migrate cleanly from `tinymist-flow.app` to `Lagrangian.app`. Require that `Lagrangian --migrate-data` has already established the `~/Library/Application Support/Lagrangian` directory and compatibility symlink in preflight (instead of copying reader data in `flow-app.py`), validate ports, artifact SHA-256 hashes, and `Tail_hosting` patches in preflight before any mutation, delegate reader installation to `tools/flow-reader/install.py --flow-manager` and login agent installation to `Lagrangian --login on` (only when a login plist already existed), update `ReaderManager.owns_agent` in `tools/flow-reader` to recognize launcher paths across the compatibility symlink, stop a running reader whose plist resolves to the installed `flow-reader` with `launchctl bootout` before `install.py`, bootstrap that plist again if installation fails, and restart it with `flow-reader --control restart` afterwards, roll back mid-flight failures by running every completed file undo and then raising, and on restore load the saved reader plist with `launchctl bootout`, a wait until the job is unloaded, `enable`, and `bootstrap`.

## Non-goals

- Do not install or launch the renamed app, restart services, or mutate the user's current 4.9 GB data during this source change.
- Do not rewrite dated verification evidence, release history, imported upstream identifiers or the Tinymist engine protocol.
- Do not alter existing profile IDs, ports, URLs, LaunchAgent labels or reader/browser storage keys.
